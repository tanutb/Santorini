How the agent learns

The Santorini agent taught itself by playing millions of games. Nobody gave it strategies; it only ever learned whether a game ended in a win or a loss. It was trained with PPO-Clip, following OpenAI Spinning Up's algorithm step for step. Here is how, with the real networks, code and training log.

The training loop

Training repeats one loop: play games, record every decision, score each one, improve the policy, then fit the value network.

These are the steps of Spinning Up's PPO-Clip pseudocode (section 9). Step through them with a real game: Coral is the learner, playing with the Hard network; Gold is an earlier agent.

Action space

75 actions in three blocks of 25, one action per square. The numbers 0–24 mean "place" or "build", depending on the phase.

Action aaPhaseMeaning

A move by worker w∈{0,1}w \in \{0, 1\} to square cc is action a=25+25w+ca = 25 + 25w + c. Moving worker 1 to C4 (square 17) is action 42. These three blocks are exactly the policy network's three output planes, flattened.

The legal-action mask
πθ(a|s)=0whenever ma=0\class{v-policy}{\pi_\theta(a \mid s)} = 0 \quad \text{whenever } m_a = 0

For every decision the rules engine computes a mask m∈{0,1}75m \in \{0, 1\}^{75}, with ma=1m_a = 1 for the legal actions, and the policy gives every other action probability 0 (see Choosing a move).

  • Place: any square without a worker.
  • Move: to one of the up to 8 neighbouring squares that has no worker or dome and is at most one level higher. The move must also leave a square to build on, unless it wins.
  • Build: on a neighbour of the worker that just moved that has no worker or dome.

Rewards

rt={+1the learner wins during step t−1the learner loses during step t0otherwiser_t = \begin{cases} +1 & \text{the learner wins during step } t \\ -1 & \text{the learner loses during step } t \\ \;\;\,0 & \text{otherwise} \end{cases}

Nothing is given for height, threats or position. The agent has to work out from results alone which moves helped.

Starting state

An empty board: all 25 squares at level 0, no workers placed, phase "place", coral to act. The learner's seat alternates between games: coral in one, gold in the next. When the learner is gold, the opponent places coral's two workers before the learner's first observation.

Episode end

  • Terminated: a worker steps up from level 2 onto level 3, and its player wins; or the player to move has no move it can complete with a build, and loses.
  • Truncated: 400 actions in total, both players' counted, and still no winner. The reward is 0, and the return is completed with the value network's estimate, because the game did not really end.

One step

step(a) applies the learner's action, then plays the opponent's actions until it is the learner's turn again or the game is over. One learner turn is therefore two steps, a move and then a build, and the opponent's whole turn happens inside the second.

server/rl/environment.pycomments added
def reset(self):
    self.learner = self.episodes % 2   # coral and gold alternate
    self.episodes += 1
    self.game = Game()
    self._opponent_turn()              # a gold learner waits for coral's placements
    return self.game

def step(self, action):
    self.game.apply(action)            # the learner's placement, move or build
    self._opponent_turn()              # the opponent acts until the learner is next
    terminated = self.game.winner is not None
    truncated = not terminated and self.game.revision >= self.max_actions
    reward = (1.0 if self.game.winner == self.learner else -1.0) if terminated else 0.0
    return self.game, reward, terminated, truncated

Inside the network

Two networks, as in Spinning Up: a policy network πθ\pi_\theta that scores every move, and a value network VϕV_\phi that judges the position. Both read the board with stacked 3×3 convolutions.

Santorini's rules are about neighbours: you move to one, build on one, and win by stepping up from one. A 3×3 convolution looks at a square and its eight neighbours with the same small filter everywhere on the board, which is exactly that shape. Spinning Up's default networks are small dense layers; convolutions suit a board better, but the training process is the same.

A residual block
F(𝐡)=Conv2⁡(ReLU⁡(Conv1⁡(𝐡)))𝐡(ℓ+1)=ReLU⁡(𝐡(ℓ)+F(𝐡(ℓ)))\begin{aligned} F(\mathbf{h}) &= \operatorname{Conv}_{2}\big(\operatorname{ReLU}(\operatorname{Conv}_{1}(\mathbf{h}))\big) \\ \mathbf{h}^{(\ell+1)} &= \operatorname{ReLU}\big(\mathbf{h}^{(\ell)} + F(\mathbf{h}^{(\ell)})\big) \end{aligned}

Each block computes a correction FF and adds it to what it received instead of replacing it. Its second convolution starts at zero, so at the start of training every block passes its input straight through (He et al., 2016).

Show the math and the code
zc(i,j)=bc+∑c′∑Δi,ΔjWc,c′(Δi,Δj)×xc′(i+Δi,j+Δj)hc(i,j)=ReLU⁡(zc(i,j))\begin{aligned} z_{c}(i,j) &= b_c + \sum_{c'} \sum_{\Delta i,\, \Delta j} W_{c,c'}(\Delta i, \Delta j) \\ &\qquad\qquad \times\, x_{c'}(i+\Delta i,\, j+\Delta j) \\ h_{c}(i,j) &= \operatorname{ReLU}\big(z_{c}(i,j)\big) \end{aligned}

A 3×3 convolution: channel cc at square (i,j)(i,j) is a weighted sum of every input channel over that square's 3×3 neighbourhood, with Δi\Delta i and Δj\Delta j running over −1,0,1-1, 0, 1. The same weights WW are used on all 25 squares, so a pattern learned in one corner works everywhere. Outside the board, inputs are zero.

class ResidualBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.first = nn.Conv2d(channels, channels, 3, padding=1)
        self.second = nn.Conv2d(channels, channels, 3, padding=1)
        # Each block starts as the identity.
        nn.init.zeros_(self.second.weight)
        nn.init.zeros_(self.second.bias)

    def forward(self, x):
        inner = torch.relu(self.first(x))
        return torch.relu(x + self.second(inner))


class ConvPolicy(nn.Module):
    # pi_theta: 3 planes x 25 squares = 75 scores
    def __init__(self, channels=64, blocks=4):
        super().__init__()
        self.stem, self.tower = residual_trunk(channels, blocks)
        self.policy = nn.Conv2d(channels, 3, 1)

    def forward(self, observations, masks):
        features = self.tower(self.stem(planes(observations)))
        scores = self.policy(features).flatten(1)
        return masked_distribution(scores, masks)


class ConvValue(nn.Module):
    # V_phi: its own trunk, then 4 planes -> 128 -> 1
    def __init__(self, channels=32, blocks=4):
        super().__init__()
        self.stem, self.tower = residual_trunk(channels, blocks)
        self.value = nn.Sequential(
            nn.Conv2d(channels, 4, 1), nn.ReLU(), nn.Flatten(),
            nn.Linear(100, 128), nn.ReLU(), nn.Linear(128, 1))

    def forward(self, observations):
        features = self.tower(self.stem(planes(observations)))
        return self.value(features).squeeze(-1)


class SeparateActorCritic(nn.Module):
    # Like Spinning Up's ac.pi and ac.v
    def __init__(self):
        super().__init__()
        self.pi = ConvPolicy(64, 4)
        self.v = ConvValue(32, 4)

Choosing a move

Scores for all 75 actions become probabilities over the legal ones, and the agent rolls the dice.

The rules engine supplies a mask of legal actions; illegal ones get probability zero. The agent then samples its move, so a 60% favourite is played about six times in ten. That keeps it varied, and it is exactly how it trained.

Masked softmax
πθ(a|s)=m(a|s)eza∑b=175m(b|s)ezb\class{v-policy}{\pi_\theta(a \mid s)} = \frac{m(a \mid s)\; e^{z_a}}{\displaystyle\sum_{b=1}^{75} m(b \mid s)\; e^{z_b}}

Raise ee to each legal score zz and divide by the total: the probabilities are positive and add up to 1. The mask mm is 1 for legal actions and 0 otherwise.

Show the math
H(π)=−∑aπ(a|s)log⁡π(a|s)H(\class{v-policy}{\pi}) = -\sum_{a} \class{v-policy}{\pi(a \mid s)}\, \log \class{v-policy}{\pi(a \mid s)}

Entropy measures how undecided the policy is. Spread evenly over nn moves, H=log⁡nH = \log n, so eHe^{H} reads as "the number of moves it is really choosing between". Certainty gives H=0H = 0.

In the code, illegal scores are set to −109-10^{9} before an ordinary softmax, which has the same effect as the mask. The coach's hint shows the single most likely move; the agent itself always samples.

Playing to learn

Many games run at once against a mix of opponents, and every decision the learner makes goes into the batch.

128 games at once8 processes, each stepping 16 games in lockstep
128 decisions eachposition, legal mask, action, its probability, the value, reward
16,384 decisionsmake the batch 𝒟k\mathcal{D}_k for one update

The opponent is part of the environment. From the learner's point of view, the next state st+1s_{t+1} is simply the next position where it has to decide, after the opponent has replied. Rewards are +1+1 for a win, −1-1 for a loss and 0 otherwise: nothing for height or threats.

Better than expected?

An advantage says how much better a decision turned out than the value network expected. It is worked out backwards from the end of the game.

The result alone is a blunt signal: a won game can contain bad moves. The value network sharpens it. Where its value rose after a decision, that decision gets a positive advantage; where it fell, a negative one. These are lines 4 and 5 of the pseudocode: rewards-to-go R^t\hat{R}_t as targets for the value network, and advantages A^t\hat{A}_t for the policy.

Generalized advantage estimation
δt=rt+γV(st+1)−V(st)A^t=δt+γλA^t+1\begin{aligned} \class{v-adv}{\delta_t} &= r_t + \gamma\, \class{v-value}{V(s_{t+1})} - \class{v-value}{V(s_t)} \\ \class{v-adv}{\hat{A}_t} &= \class{v-adv}{\delta_t} + \gamma\lambda\, \class{v-adv}{\hat{A}_{t+1}} \end{aligned}

The surprise δt\delta_t is the reward plus the value of where you landed, minus the value of where you were. The advantage adds a fading share (γλ\gamma\lambda per step, with Spinning Up's λ=0.97\lambda = 0.97) of every later surprise. With λ=0\lambda = 0 it is one step of surprise; with λ=1\lambda = 1 it is the final result minus the value network's guess.

Show the math and the code
R^t=∑k=0T−t−1γkrt+kVϕ(s)≈𝔼[R^t|st=s]\begin{aligned} \hat{R}_t &= \sum_{k=0}^{T-t-1} \gamma^{k}\, r_{t+k} \\ \class{v-value}{V_\phi(s)} &\approx \mathbb{E}\big[\,\hat{R}_t \mid s_t = s\,\big] \end{aligned}

Rewards-to-go and value: R^t\hat{R}_t adds up the rewards from decision tt to the end of the game, each one γ=0.99\gamma = 0.99 times less per decision. Because the only reward comes at the end, a win kk decisions away is worth γk\gamma^{k} now. The value network is fitted to R^t\hat{R}_t in line 7. When the batch ends mid-game, the sum is completed with the value of the next position, as Spinning Up does.

A^t=∑l=0∞(γλ)lδt+l\class{v-adv}{\hat{A}_t} = \sum_{l=0}^{\infty} (\gamma\lambda)^{l}\, \class{v-adv}{\delta_{t+l}}

Unrolled: the advantage is a discounted sum of surprises, with λ=0.97\lambda = 0.97. At the end of a game the sum stops; a game cut off at 400 actions still adds the value of its last position.

A^t←A^t−mean⁡(A^)std⁡(A^)+10−8\class{v-adv}{\hat{A}_t} \leftarrow \frac{\class{v-adv}{\hat{A}_t} - \operatorname{mean}(\class{v-adv}{\hat{A}})}{\operatorname{std}(\class{v-adv}{\hat{A}}) + 10^{-8}}

Normalising: before the update, advantages are rescaled across the batch to average 0 and spread 1, so step sizes do not depend on how large rewards happen to be.

server/rl/ppo.pyshortened
def compute_gae(rewards, values, next_values, terminated,
                boundaries, gamma=0.99, gae_lambda=0.97):
    advantages = torch.zeros_like(rewards)
    running = torch.zeros(rewards.shape[1:])
    # Backwards from the end of the batch.
    for t in reversed(range(len(rewards))):
        alive = (~terminated[t]).float()
        delta = rewards[t] + gamma * next_values[t] * alive - values[t]
        carry = gamma * gae_lambda * (~boundaries[t]).float()
        running = delta + carry * running
        advantages[t] = running
    return advantages


def rewards_to_go(rewards, next_values, terminated, boundaries,
                  gamma=0.99):
    returns = torch.zeros_like(rewards)
    last = len(rewards) - 1
    for t in reversed(range(len(rewards))):
        # A real ending adds nothing; a cut adds the next value.
        bootstrap = next_values[t] * (~terminated[t]).float()
        if t == last:
            tail = bootstrap
        else:
            tail = torch.where(boundaries[t], bootstrap, returns[t + 1])
        returns[t] = rewards[t] + gamma * tail
    return returns

The PPO-Clip objective

Make better-than-expected moves more likely and worse ones less likely, but stop once a probability has moved by 20%.

The update reuses each batch for several passes. To keep it honest, it compares the new probability of each recorded move with the old one through a ratio ρ\rho, and clips the objective so there is nothing to gain from pushing ρ\rho outside [0.8, 1.2][0.8,\ 1.2].

The clipped surrogate objective
LCLIP=𝔼^t[min⁡(ut,vt)]ut=ρtA^tvt=clip⁡(ρt,1−ϵ,1+ϵ)A^tρt=πθ(at|st)πold(at|st)\begin{aligned} L^{\text{CLIP}} &= \hat{\mathbb{E}}_t\big[\min(u_t,\; v_t)\big] \\ u_t &= \class{v-policy}{\rho_t}\,\class{v-adv}{\hat{A}_t} \\ v_t &= \operatorname{clip}(\class{v-policy}{\rho_t},\, \class{v-limit}{1-\epsilon},\, \class{v-limit}{1+\epsilon})\,\class{v-adv}{\hat{A}_t} \\ \class{v-policy}{\rho_t} &= \frac{\class{v-policy}{\pi_\theta(a_t \mid s_t)}}{\class{v-policy}{\pi_{\text{old}}(a_t \mid s_t)}} \end{aligned}

Take the smaller of the plain objective utu_t and the clipped one vtv_t. Moving a probability more than ϵ=0.2\epsilon = 0.2 in the helpful direction earns nothing extra; moving it in the harmful direction is never clipped, so mistakes are paid for in full.

Show the math and the code
∇θJ(θ)=𝔼t[∇θlog⁡πθ(at|st)A^t]\nabla_\theta J(\theta) = \mathbb{E}_t\!\left[\, \nabla_\theta \log \class{v-policy}{\pi_\theta(a_t \mid s_t)}\; \class{v-adv}{\hat{A}_t} \,\right]

Where it starts, the policy gradient: to win more often, raise the log-probability of each action in proportion to its advantage (Williams, 1992; Sutton et al., 2000). Followed naively, each batch supports only one small step, and a step slightly too big can collapse the policy onto a few moves.

ρt(θ)=πθ(at|st)πold(at|st)=exp⁡(log⁡πθ(at|st)−log⁡πold(at|st))\begin{aligned} \class{v-policy}{\rho_t(\theta)} &= \frac{\class{v-policy}{\pi_\theta(a_t \mid s_t)}}{\class{v-policy}{\pi_{\text{old}}(a_t \mid s_t)}} \\ &= \exp\big(\log \class{v-policy}{\pi_\theta(a_t \mid s_t)} \\ &\qquad\; - \log \class{v-policy}{\pi_{\text{old}}(a_t \mid s_t)}\big) \end{aligned}

The ratio starts at 1, because the weights being trained begin equal to the ones that played. ρtA^t\rho_t\hat{A}_t has the policy gradient's gradient at ρt=1\rho_t = 1, and lets the same batch be reused for several passes. The clip keeps those passes from running away.

def clipped_policy_loss(log_probs, old_log_probs, advantages, clip):
    ratio = (log_probs - old_log_probs).exp()
    ordinary = ratio * advantages
    clipped = ratio.clamp(1 - clip, 1 + clip) * advantages
    # Minus, because optimisers minimise.
    return -torch.minimum(ordinary, clipped).mean()

One update

Each update makes two separate fits, as in Spinning Up: first the policy, with a brake, then the value network. Both use a few quick passes over the batch.

Line 6maxθ⁡LCLIP\max_\theta L^{\text{CLIP}}4 passes over the batch in minibatches of 2,048: up to 32 Adam steps on θ\theta, stopping once the KL passes 0.015
Line 7minϕ⁡(Vϕ−R^)2\min_\phi (V_\phi - \hat{R})^24 passes in minibatches of 2,048: 32 Adam steps on ϕ\phi, learning rate 0.001
The early stop
D^KL=𝔼^t[log⁡πθk(at|st)−log⁡πθ(at|st)]stop when D^KL>1.5×0.01\begin{aligned} \hat{D}_{\mathrm{KL}} &= \hat{\mathbb{E}}_t\big[\log \class{v-policy}{\pi_{\theta_k}(a_t \mid s_t)} \\ &\qquad\; - \log \class{v-policy}{\pi_\theta(a_t \mid s_t)}\big] \\ \text{stop when } \hat{D}_{\mathrm{KL}} &> 1.5 \times 0.01 \end{aligned}

Before each policy step, the trainer estimates the KL divergence between the policy that played the games and the one being trained, from log-probabilities it already has. Past 0.015, the policy has moved far enough for one batch.

Is KL part of PPO-Clip? Plus the code

The KL check is a brake, not part of the objective. PPO-Clip's objective needs no KL divergence: the clip replaces it. (The paper's other variant, PPO-Penalty, adds a KL term to the loss instead.) Spinning Up adds this early stop because the clip is not a hard limit: it zeroes the gradient only for decisions already outside [1−ϵ, 1+ϵ][1-\epsilon,\ 1+\epsilon], while the others can keep moving the shared weights. The estimate never enters the gradient.

Unlike some PPO versions, this process has no entropy bonus and no gradient clipping, and the two networks have separate Adam optimisers. Advantages are normalised over the batch before the policy steps.

server/rl/ppo.pyshortened
def update(model, optimizers, batch, config):
    pi_optimizer, v_optimizer = optimizers
    obs, masks = batch["observations"], batch["masks"]
    actions, old = batch["actions"], batch["log_probs"]
    adv = batch["advantages"]
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)

    # Line 6: policy steps, until the policy has moved enough.
    # 4 shuffled passes in minibatches of 2,048 decisions.
    for ids in step_schedule(len(adv), config):
        log_probs = model.pi(obs[ids], masks[ids]).log_prob(actions[ids])
        loss = clipped_policy_loss(log_probs, old[ids], adv[ids], config.clip)
        kl = (old[ids] - log_probs).mean().item()      # approx. KL
        if kl > 1.5 * config.target_kl:                # 1.5 x 0.01
            break
        pi_optimizer.zero_grad()
        loss.backward()
        pi_optimizer.step()

    # Line 7: fit the value network to the rewards-to-go.
    for ids in step_schedule(len(adv), config):
        error = model.v(obs[ids]) - batch["returns"][ids]
        loss = error.square().mean()
        v_optimizer.zero_grad()
        loss.backward()
        v_optimizer.step()

The algorithm on one page

This agent was trained with Spinning Up's PPO-Clip process, line for line. The networks, the game, and how many gradient steps lines 6 and 7 take are what differ.

What happened in training

The training log of the run that produced the Hard agent.

The value network failed at update 550. In that update's fit, the four channels at the top of its value head stopped responding to every position. A ReLU that outputs 0 everywhere passes back no gradient, so they never recovered, and from then on the network predicted 0.51 for every position: the value error above jumps at update 550 and stays up. The policy kept improving, because the advantages still credited moves in won games and blamed moves in lost ones, just less precisely. After training, a fresh value network was fit on about 102,000 games played by the frozen final policy, which is line 7 of the pseudocode on its own. That refit network is the one in this page's figures.

Details that made it work

Masking, not punishing

Illegal moves get probability exactly 0, so no games are wasted learning the rules. The stored mask is reused in the update, so ratios compare like with like.

One point of view

Inputs are always "mine" and "theirs", so what it learns playing first carries over to playing second.

Careful starting weights

The policy head starts tiny, so the first policy is nearly uniform over legal moves, and each residual block starts as the identity.

Two brakes

The clip removes the reason to move a probability more than 20%, and the KL early stop ends the policy steps once the policy as a whole has moved far enough.

A changing opponent pool

A snapshot every 10 updates, the 10 latest kept, plus fixed programs and earlier agents.

Separate networks

Because the policy and value networks share nothing, fitting the value network can never disturb the policy after its KL check, which is why Spinning Up keeps them apart.

At play time only: symmetry

The board looks the same in its eight rotations and reflections, but the network does not know that. Each game the site shows it a random orientation, so its openings vary without changing its strength.

Glossary and reading

Actor
The policy network πθ\pi_\theta, which chooses moves.
Advantage
How much better a decision turned out than the value network expected.
Batch
All the decisions collected for one update: 16,384 here.
Critic
The value network VϕV_\phi, which estimates how good a position is.
Discount γ\gamma
How much a reward one decision later is worth compared with one now.
Entropy
How spread out the policy's probabilities are.
GAE λ\lambda
How far ahead advantages look, trading noise against reliance on the value network.
KL divergence
A measure of how different two probability distributions are; here only a brake.
Rewards-to-go
R^t\hat{R}_t: the discounted rewards from a decision to the end of the game, the value network's target.
Logit
A raw score before softmax turns scores into probabilities.
Snapshot
A frozen copy of the agent, kept as an opponent.
